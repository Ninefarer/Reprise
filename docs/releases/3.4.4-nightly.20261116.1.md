# Reprise 3.4.4-nightly.20261116.1 Nightly

Per-machine NSIS installation shared with Stable 3.4.4. Notification behavior matches Nightly `3.4.4-nightly.20261115.2`, which Stable 3.4.4 now includes.

## Implementation

- Set `bundle.windows.nsis.installMode` to `perMachine` in both `src-tauri/tauri.conf.json` and `src-tauri/tauri.nightly.conf.json`. Tauri 2.12.4 then uses `RequestExecutionLevel admin`, installs to `%ProgramFiles%\${PRODUCTNAME}`, and writes the uninstall entry under HKLM.
- The updater launch mode is unchanged: `plugins.updater.windows.installMode` remains `passive`, so an installed app still starts the NSIS package with `/P /R /UPDATE` through `ShellExecuteW` `open`. Administrator consent is requested by the installer manifest.
- `src-tauri/windows/hooks.nsh` runs before files are copied. When HKCU `Software\${MANUFACTURER}\${PRODUCTNAME}` records a different directory whose path ends with the product name, the hook closes that executable, deletes `reprise.exe` and `uninstall.exe` there, removes the empty directory, and deletes that HKCU uninstall key. It rewrites a Run-key value only when that value still points at the old executable, and then retargets the current user's Start Menu and desktop shortcuts.
- The hook does not delete `%AppData%` or `%LocalAppData%` application data. Stable data stays under `com.reprise.desktop` and Nightly data under `com.reprise.nightly`.
- The installed-upgrade fingerprint now includes the NSIS install mode, hook path and hook source. The previous current-user acceptance receipt no longer authorizes publication.

## Validation

- `npm test` (`vitest run`): exit 1. 215 passed, 1 failed, 0 skipped, 216 total. The failure is `right notification panel > finishes exit motion before unmounting and cancels it safely when reopened`: Escape did not set `data-exiting="true"`. An earlier full run in the same environment failed that test and `closes immediately with decorative motion disabled`. A separate probe, not committed, waited 50 ms after Ctrl+Shift+N and both tests passed. jsdom runs `requestAnimationFrame` on a 16 ms interval and user-event's keyboard delay is 0, so Escape can be dispatched before the panel focuses its first button. The panel code was not changed in this release.
- `npm run build` (`tsc && vite build`): exit 0. Production output was written under `dist/`.
- `cargo fmt --manifest-path src-tauri/Cargo.toml --check`: exit 0. Toolchain `rustc 1.100.0`.
- `cargo check --manifest-path src-tauri/Cargo.toml`: exit 101. The Linux host cannot resolve the `windows` crate, which `src/visuals.rs` uses from `native_glass`. That dependency is declared only for `cfg(windows)`.
- `cargo test --manifest-path src-tauri/Cargo.toml`: exit 101. Same host compile error, so no Rust tests executed.
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`: exit 101. Same host compile error.
- `cargo check --manifest-path src-tauri/Cargo.toml --target x86_64-pc-windows-gnu`: the first attempt exited 101 because `ring` could not find `x86_64-w64-mingw32-gcc`. After that compiler was available, the same command exited 0.
- `cargo test --manifest-path src-tauri/Cargo.toml --target x86_64-pc-windows-gnu --no-run`: exit 0. The Windows test executable compiled. It was not executed; Wine is not available here.
- `cargo clippy --manifest-path src-tauri/Cargo.toml --target x86_64-pc-windows-gnu --all-targets -- -D warnings`: exit 0.
- The NSIS hook was reviewed against the Tauri CLI 2.12.4 installer template. It was not compiled with `makensis` or installed on Windows.

## Installation

Update through the Nightly feed or run the new `Reprise.Nightly_3.4.4-nightly.20261116.1_x64-setup.exe` over the existing Nightly installation. The installer asks for administrator approval. Keep Nightly's separate task data. Stable 3.4.4 is a separate installation and database.

## Known limitations

- A Windows install and an installed upgrade from a per-user copy have not been executed for this build.
- If approval elevates a different administrator account, the installer reads that account's HKCU and can leave the original user's per-user copy and shortcuts in place beside the Program Files install.
- Shortcuts outside the current user's Start Menu and desktop, including taskbar pins, are not rewritten.
- Declining the approval prompt leaves the current installation unchanged.
- Deletion Undo still cannot recall a notification already submitted to Windows, and restarting the app discards a pending deletion receipt.
