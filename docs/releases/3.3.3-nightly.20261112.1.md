# Reprise 3.3.3 Nightly ? 2026-11-12.1

A quality-testing build on top of the Stable 3.3.2 signed updater bootstrap. Install manually once over your existing Nightly installation to enable its feed. Nightly retains its separate identity and database.

## Changes

- Protect unsaved profile and reminder drafts when navigating, replaying setup or quitting through the profile menu. The prompt offers Save, Discard and Keep editing; rejected saves keep the draft. Appearance and pictures still save immediately.
- Include the 3.3.1 task-editor hotfix so status buttons submit current edits rather than the original task.
- Handle Windows' missing notification permission record (`0x80070490`) separately from explicitly disabled notifications. The test action is under Nightly's Advanced / Diagnostics; ordinary reminder preferences stay visible.
- Filter Nightly release history to Nightly entries, omit its redundant What's New button, and retain the Nightly disclosure.
- Tighten user-facing copy in setup, task details, search, Settings and current guides. Add an accessible task-dialog name and polite command-palette result announcements.
- Add per-window `?perf=1` instrumentation with a 256-sample cap, snapshot reasons/counts/bytes, optional backend phase timings and commit/save durations. No task contents are retained in samples; default launches do not record or transmit measurements.
- Configure signed GitHub update feeds. Checks start after onboarding, repeat every six hours and can be requested in Settings. Available offers are deduplicated; installation remains explicit. Stable and prerelease versions cannot cross channels.

## Verification

- Local frontend tests: 171 passed after the final channel metadata merge; the signed release workflow reruns the final suite, Rust tests, formatting, strict Clippy and production build before publication.
- Local Rust tests: 49 passed, one native-toast probe intentionally ignored because it sends a real Windows notification. The artifact verifier passed both checks without skips.
- An installed signed QA build updated from `.900` to `.901`, restarted, and retained its synthetic task, profile and SQLite integrity. Tampered bytes, mismatched signed versions, a different channel and a stale offer were rejected. See `docs/updater-acceptance.json` for exact source, hashes and run.
- Actual desktop testing confirmed that the Settings navigation prompt appears, Keep editing retains the draft, and Discard restores the saved profile. The isolated updated app remained usable after restart.

## Testing notes

- The installed-upgrade acceptance used loopback HTTP behind an explicit QA-only Cargo feature and separate identity. Production builds require HTTPS and do not enable that feature; published GitHub assets are verified separately.
- No refresh-frequency or lifecycle changes were made. Full representative-load latency and long-session measurements remain follow-up work; synthetic query timings are not claimed as application responsiveness.
- Native Glass, multi-monitor DPI, physical trackpad input and the full accessibility/theme matrix were not freshly requalified in this pass. Existing composition and lifecycle behavior remain unchanged.
- The Settings guard covers in-app navigation and profile-menu Quit. Native tray Quit and OS shutdown retain their existing behavior.
